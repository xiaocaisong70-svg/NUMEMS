## 本次变更

1. 最新白名单同时约束分配、办理计划和邀请领取。排队申请取消；已预留、已发或在途的邀请保留真实容量和原租约，按官方当前状态只撤回邀请，保护已加入成员。已经领取的浏览器动作可能在途，系统核实真实结果后再执行撤邀，不声称跨系统操作具有原子性。
2. 告警按故障和事件去重；只有新鲜的官方、云端和本机结案证据一致时才能关闭旧事件。未配置 HTTPS 网关时明确是本机记录及网页告警，不冒充已发送站外通知。不启动模型、Codex 或桌面通知窗口。
3. 恢复退避按已验证的健康周期重置；云端与本机只允许 5 秒以内的有界时钟差，本机官方快照时间不能晚于检查时间。重启进程、更新失败时间或单纯空闲均不会重置连续失败的退避。新周期首次等待 60 秒；未知结果及原租约仍保持安全暂停。
4. 空闲时约每 120 秒进行两次完整官方快照核对。专用 CAS 校验避免旧对账覆盖新租约、故障或新证据。网页显示最近官方核对时间，超过 3 分钟提示过期；不承诺官方后台变更能立即推送。
5. 主状态保留近期记录和所有安全必需数据；旧记录事务归档到独立 D1 表并分页查询。申请、续期增加员工级固定窗口限流。归档总量达到 50,000 条时提示管理员评估容量；历史不会被静默删除，详细规则见 `HISTORY-V12.md`。

## 发布门槛

规则、权限、并发、浏览器夹具、真实隔离 D1、类型与生产构建全部通过后才可发布。发布前保留 V11 完整源码、Git bundle、本机实际运行文件与配置、计划任务导出及校验清单。不得上传配置、Cookie、令牌、浏览器档案、办理日志或生产数据。

## 回退触发条件

构建或迁移失败；核心申请、续期、邀请、核对或回收回归；白名单越权；重复成员动作；容量/角色/工作空间不符；归档记录缺失；新旧状态或回执不一致；异常窗口出现在用户桌面。官方需要重新登录或安全验证时先按既有规则暂停核查，不把验证码问题自动解释为可绕过的程序故障。

## 回退顺序

1. 禁用 `NUMEMS-Agentless` 计划任务，运行 `node scripts/agentless/stop.mjs --timeout-ms 300000` 正常结案停机。不能删除锁、`operation.json`、租约或不明回执。
2. 保存当前故障、D1 及本机证据。核对尚未结束的实际邀请/移除，按原租约结案；不能通过恢复旧数据使其消失。
3. 云端暂停成员办理与队列分配。运行 `node scripts/agentless/host.mjs admin rollback-status` 读取当前 D1 修订，再运行 `node scripts/agentless/host.mjs admin prepare-v11-rollback 修订号` 进行受保护的数据准备。V12 的 `restoreV11History` 仅在执行器和调度均关闭、无租约/隔离/故障来源且无待办 `whitelist_revoked` 时，把归档补回**当前**状态。CAS 冲突或超过 V11 单文档安全容量时拒绝写入，保留当前数据和归档；不得用过时的整库快照覆盖新申请。
4. 原生 Sites 重新部署已保存的 V11：`appgprj_6adace8f4e7481919901f886e4a0a2f2~appgver_1aef8183d3a881918f96b7f5e76c3f42`。新增归档表保留，不执行降级删表。
5. 按 V11 本机文件清单逐项恢复实际运行源码；V12 新文件逐项移到回退证据目录。保留依赖、配置、浏览器档案、D1、当前办理日志和回执。`browser-retry.json` 若为已验证的 V12 健康标记，先归档该标记，按其 `legacyRetryRecord` 恢复 V11 格式；不存在旧记录时也必须先归档并通过当前安全核验，才能从空的退避历史开始。未知或较新故障记录不覆盖。
6. 校验源码哈希、V11 类型/构建、官方完整成员与邀请、4 个付费席位、Owner、当前申请和原租约全部一致后，仅启用一个执行器。
