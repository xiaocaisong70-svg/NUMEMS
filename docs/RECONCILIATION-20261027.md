# 官方成员状态对账修复（2026-10-27）

一次邀请超时前后的官方页面读取中，席位卡数字与跨页面读取的成员/邀请数不一致。原执行器将其记录为未开始成员写入的 unknown，随后停机；之后旧 worker 的进程号被系统进程复用，看护程序无法确认旧进程已退出，故持续保持暂停。历史日志没有保存数量，不能断定导致不一致的是分页、加载还是官方计数延迟。

本次修复保持原有完整名单、身份、角色、已购容量、双快照及领取/回执检查。操作前遇到明确名单数量不一致时只重新完整读取一次；仍不一致且确认服务端已记录未开始动作的 browser_unavailable 后，允许已有的只读恢复流程继续核对。已经领取、写入结果不明、身份或容量异常时不降级、不重做外部动作。

看护程序仅在只读系统进程信息证实同一 PID 被更晚创建的非 Node 进程复用时允许继续到原有条件检查；未知身份、同为 Node 的进程或未结案记录仍阻止启动，隔离宿主持有互斥锁后再次核对。不会终止占用该 PID 的其他程序。

新增受限正式环境核对入口：必须是指定的未开始成员写入故障、没有云端租约/隔离项、本机日志已结案；两次新的完整官方快照必须一致，期间重复检查计划和日志。服务端用故障审计 ID 原子校验指定暂停未变，再对账并记录恢复。超时目标在官方名单已经加入时保留成员并转为使用中。官方不提供精确接受时间，尚未开始计时的申请按核对确认时间计算租期；已存在的有效租期不因观察重置。

官方完整快照可识别外部加入或移除的状态变化；有相应租约、隔离、证据早于申请更新或容量异常时不擅自完成、重试或加购。真实操作仍需独占领取、实际核对和对应回执；任何未知结果保留原记录。

回退时先停用后续调度并请求当前批次正常结束，保留本机日志、租约和云端状态。可按修复前源码提交和 Sites 第 6 版恢复代码，不以旧备份覆盖已经发生的业务操作。必须复查官方完整名单、云端租约和唯一执行器后恢复运行。
