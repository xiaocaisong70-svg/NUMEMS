# V14.1：修复救援轮次被提前结案

本次修复针对 V14 的实际运行故障。V14 归档源码是 `fa24df3f901368edfa9936ee3ed193d25ab39c76`，GitHub 归档提交是 `7494e5ec5cf645f24aea86590a9c3b203899d80f`，Tag 是 `agentless-v14`；对应 Sites 内部发布版本为 17。产品版本与 Sites 保存版本分别计数，不能混用。V14.1 的最终源码、部署标识和测试总数由本次发布记录填写，本说明本身不代表已经安装或验收完成。

## 实际根因

独立连接的 App Server 对桌面中仍在运行的救援轮次返回了 `status: interrupted`，同时 `completedAt: null`。旧代码只判断状态枚举，把 `interrupted` 当作模型已经停止，因此过早调用 `finish_fault_rescue`，关闭了尚在使用的票据。

本次实测中，救援票据于 13:19:58 UTC 创建，期限为 13:24:58 UTC。13:21:20 UTC 的错误停止证据没有完成时间，13:21:21 UTC 却已结案；后续模型申请原票据权限时被拒绝。相同精确轮次直到 13:25:54 UTC 才出现真正的 `completed` 和有效完成时间。没有因此发生新的成员写入，但后备办理失效，影响了真实申请与回收。这是代码缺陷，不能归因于员工未配合，也不能将其描述为成功的无人值守处理。

`thread.status: notLoaded`、队列中暂时找不到消息、模型自己提交 ACK，以及仅有终态枚举，都不足以证明相关模型执行已经停止。同一根轮次的后续 continuation 仍在运行时，也不能仅凭原始消息所在轮次已经结束而释放互斥。

## 修复范围

- 每个关联祖先轮次及已读取的同根后续轮次，都必须同时具备终态状态、有效开始时间和有效完成时间；完成时间须不早于开始时间，且不晚于观察时间。`interrupted` 或 `failed` 没有完成时间时继续保留互斥。
- 使用有界、倒序的 summary 分页，不读取聊天工具正文。找到原消息及根轮次前先收集更新的关联轮次；准备接受终态时再读取最新页，元数据发生变化则不接受本次停止证明。
- 生成明确的 `terminalEvidence`、祖先链 `terminalChain`、关联集合 `terminalFamily` 和分页复核标记。纯数据校验器不启动浏览器、模型或协议进程，供各消费端统一验证。
- 旧持久化证明缺少上述字段时不能继续作为停止依据。对历史误结案仅追加新的真实终态验证记录，保留原错误证明、票据、原租约和操作日志供追溯；不通过修改旧时间或删除文件掩盖问题。
- 后备处理仍须满足服务端期限、冻结目标、单次领取/授权、完整官方观察和原操作回执等原有约束。未知点击结果不得重新执行。修复终态判断不等于延长票据，也不为已经过期的票据重新授予写权限。

## Windows 状态文件提交冲突

本轮完整回归还复现了 Windows 并发短时读取导致原子 `rename` 返回 `EPERM` 的情况。修复仅对 Windows 的短暂共享冲突重试同一个已完整写入的临时文件提交，最多 7 次，计划等待共 430 毫秒，按单调时钟执行 500 毫秒的重试截止检查；不重新生成内容、不删除目标文件，也不重新执行任何成员或消息动作。该检查不能硬取消已经进入操作系统的文件 I/O。持续失败仍抛错并保留原文件和临时证据。此机制不提供多写者 CAS，原有租约、派发见证和执行器互斥仍然必需。

完整回归命令增加每项 120 秒超时；受限环境中浏览器夹具若无法启动，应明确失败，不能无限等待或视为通过。
