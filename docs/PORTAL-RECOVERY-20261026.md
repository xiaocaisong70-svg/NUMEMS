# 门户网络超时恢复（2026-10-26）

## 本次原因

2026-10-26 00:19（America/Los_Angeles），常驻程序因 `page.evaluate: TimeoutError: signal timed out` 退出。原错误没有请求类型或阶段信息，统一写成 unknown；看门狗正确拒绝重复不确定操作，但一次普通门户请求超时也会让后续工作长期暂停。旧日志无法准确区分超时发生于身份、状态还是队列请求，因此没有按错误字符串自动清除 unknown。

处理前保存源码标签 `before-portal-read-timeout-20261026`、完整源码 tar、原任务 XML及本机诊断。最新云端没有租约/全局故障，本机 journal settled；只读检查核实管理员、完整官方名单、4 个已购席位和隔离桌面后，独立单次脚本完成原 God Z 到期回收，并发出 NING place 的官方邀请。之后员工另外提交的新申请作为独立记录处理。邀请发出并不代表本人已经接受，仍遵循原 5 分钟超时保护规则。

## 修复

1. PortalClient 区分身份 GET、状态读取和原写 RPC。只有浏览器返回明确的超时/网络故障，或初次只读导航的已知网络错误，才产生有请求阶段证据的专用错误。认证、证书、权限、坏 JSON、未知协议和未结构化异常保持停止。
2. 新增管理员 RPC `refresh_seat_queue`：只进行纯原子队列 tick 和心跳，返回当前队列统计及计划。无论提醒模式如何，它都不投递邮件、不联系外部服务、不操作官方成员。原 `process_seat_queue` 的 relay 行为保留，但普通执行器不再用它轮询。
3. 对上述安全请求的网络故障，且 journal 缺省或 settled、无保留租约/回执时，程序进入本机 `recovering/portal_recovery`，按 5/15/30/60/120/300 秒退避，之后每 300 秒检查。检查过程中不领取成员操作；停机请求最多在一秒等待片段后生效。
4. 恢复要核对管理员/工作空间、无未完成云端租约/全局故障、完整官方名单/Owner/角色/容量，再复查计划。不会修改云端故障或把 HTTP 成功当作已完成成员操作。
5. 新增恢复错误的本机结构化证据也供看门狗核查；只有相应证据和已结案日志才可在进程中断后重启。旧 unknown 不会自动降级。
6. 若身份 GET 在 claim POST 发出前失败，只允许匹配的本机 claiming 记录写入 claimNotSent 证明后结案。POST 已发、已领取、已点击、completing 或结果不明不能走此路径，原记录继续保留。

申请、FIFO、续期、到期判断、网页提醒、已加入保护、管理员和席位容量保护沿用原规则。日常程序不调用模型、不唤醒 Codex、不打开用户桌面窗口。新 RPC 随 Sites 新版本发布，现有公开登录入口、白名单和数据库保持原配置。

## 验证与运行

规则回归包含旧业务规则、新增传输分类、超过三次读取失败后的持续恢复、claim/complete 未知结果不重做、等待中停止、恢复时新租约、错 Owner/容量、纯刷新在 relay 模式不发邮件、匿名/员工/跨源拒绝。现有四个离线浏览器夹具本轮不重复运行；不宣称全量浏览器回归通过。TypeScript 与 Sites 生产构建作为发布门槛。

状态位于忽略上传的 `.sites-runtime/agentless/status.json`，有 checkedAt、failureCode、readFailure、下一次检查时间；看门狗仍使用原计划任务。错误证据不包含密码、Cookie 或租约 token。

## 回退

构建失败、权限/成员规则退化、错误重试或隔离证据异常时，停止发布或请求当前程序优雅停机，并保存原租约、日志和任务 XML。恢复 `before-portal-read-timeout-20261026` 的本机源码；云端可重新部署原 Sites 第 5 版。数据库及已发生的邀请/移除不随源码回退。先核对官方状态、原租约、唯一执行器后再恢复原任务。回退会恢复旧网络故障处理的限制。

升级必须先成功部署新云端接口，再启动新本机执行器；如果接口不存在，程序保持错误状态，不回退到可能投递邮件的旧 RPC。绝不删除操作日志或改员工截止时间来强行继续。
