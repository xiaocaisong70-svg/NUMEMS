# 五分钟加入与排队状态

仅更新原版 Sites 站点，使用同一 D1 状态与 CAS 原子更新。优化版不变。

## 状态与时间

`queued → pending_invite → invited → active → pending_removal → completed`。
`invited` 在 `joinDeadlineAt <= serverNow` 时进入 `pending_removal`，
原因标记为 `invitation_expired`；提前释放为 `release`，使用到期为 `lease_expired`。
尚未完成真实撤回／移除时继续占用容量。确认无成员、无邀请后才分配下一位。

加入截止时间是实际邀请发送记录加300秒。执行器须传 `invitationSentAt`，
必须在独占办理开始之后、官方核实之前。历史无法确定发送时刻的记录只能用首次确认时刻；
不得把它表述为精确邮件到达时间。既有使用截止时间不改动。

用户“我已接受，核对加入”只记录幂等的核对请求，不证明加入、不启动使用期、不延长窗口。
到时先读完整官方列表。已是普通成员则确认使用，即使首次核对发生在截止后，也不能
根据缺少的点击时间推断逾期；仍在邀请列表者撤回。撤回开始后若员工成为普通成员，
用独立的 `joined` 官方快照回执安全结束原租约，保留成员及席位，不把撤回结果记为成功。
只有核实该邮箱既非成员也无邀请才释放容量、转派下一位。
该规则保证不因核对延迟误移除已加入的人，但无法严格拒绝所有截止后加入的人。

提前释放会取消本轮尚未发送的到期提醒，重复点击不会增加回收任务；进入回收后不能续期。
员工只能操作自己的申请，管理员和 Owner 保护不变。

## 多端与估算

- 服务端 UTC 为唯一时间基准。客户端使用服务端时间加 `performance.now()` 单调时间，
  不依赖设备墙钟；每秒显示倒计时，刷新、换设备不会重置。
- 已登录页面每10秒重新取得服务端快照，回到前台立即刷新。45秒未同步时显示待同步，
  不再把过时计时或估算当作当前结果；实际操作由服务端再次检查。
- 已授权读取与定时检查均可运行纯队列推进。关闭网页后由本机普通检查程序继续。
  本机离线、登录失效、审批或浏览器办理延迟会推迟实际动作，不宣称第300秒必定撤回。
- 等候人数仅统计 `queued`；可分配数扣除管理员保留、待邀请、待接受、使用中及待回收。
- 使用同一提交顺序进行多席位 FIFO 估算；相同时间保持插入顺序。当前邀请分别按
  “截止仍未加入”和“截止前加入并用足申请时长”形成时间区间；前方排队按其完整申请时长
  加5分钟邀请窗口模拟。不包含外部办理延迟，因此是参考时间而非承诺。
- 固定成员、未完成邀请／回收、被隔离的成员无法确定可用时间；没有其他可预测席位时
  显示“暂无法估算”。暂停或未盘点显示等待恢复／核对。邮件隔离不影响成员容量估算。
- 普通员工只得到总人数、可用数和本人估算；不暴露其他员工邮箱、用途或请求标识。
