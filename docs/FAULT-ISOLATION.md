# 故障隔离修复 · 2026-10-20

用户已要求同时更新原版和优化版。此次授权覆盖两份源码、两个独立 Sites 部署和旧版检查程序恢复；不启用尚未完成切换验收的优化版执行器。

## 行为

| 故障 | 暂停范围 | 恢复依据 |
|---|---|---|
| 邮件发送失败或结果不明 | 该通知；保留租约与回执线索 | 真实发信消息 ID；禁止自动重发 |
| 邮件通道配置无效 | 仅邮件通道 | 配置修复；不切换到另一个通道补发 |
| 明确局限于单一成员的失败 | 此邮箱的成员操作 | 操作后完整官方快照 |
| 单个动作的审批要求或拒绝 | 该目标 | 保留原审批，管理员核查后处理 |
| 登录、工作空间、容量、角色或未知异常 | 全局 | 未完成租约核实完毕，管理员重新核对完整官方状态 |
| 消息投递结果不明、批次没有回执 | 全局 | 保留投递意图，人工核实，禁止盲目重发 |

活跃操作继续采用全局独占租约；只有已明确归类的失败才移入目标隔离列表。成员尚未核实移除时仍计占用。一个成员的成功回执不会清除另一个目标或全局故障。

本地检查程序保存批次中的确切事件，只有读到相应云端隔离记录才允许后续工作继续。混合批次中未处理的其它事件不会被误标记完成。

旧版已经存在的 `ack_blocked` 没有完整事件元数据，保持关闭，不自动猜测原因或清除。恢复时保留原 ack 和恢复日志，先核实官方状态及旧故障是否仍有效。

## 验证

两版共用 `tests/failure-isolation.test.mjs`，覆盖邮件与成员隔离、同一员工到期回收、禁止重发、审批保留、全局故障、真实回执核对、混合批次、邮件通道和旧记录兼容。新增逻辑不依赖模型判断队列；外部浏览器与 Gmail 办理仍按原授权流程运行。

线上 `/api/health` 返回 `faultIsolationVersion: 1`；此标识仅证明运行了修复版本，不代表任何具体成员已经移除。
