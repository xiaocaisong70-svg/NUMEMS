# V13：有限恢复与一次性故障诊断

基于 V12 优化安全检查处理；保留同一线上地址、申请与 FIFO、1–3 小时使用和续期、五分钟邀请时限、已加入成员保护、网页三十分钟提醒、提前释放、员工白名单、隔离桌面和原租约结案。

正常任务继续由普通程序运行，不使用模型。出现安全检查后先有限等待、完整名单重读和一次同配置上下文重启。泛化 challenge 不再等同于需要真人认证。若仍无法恢复，才持久化独占故障票据，通知网页并投递一次只读 Codex 诊断。诊断不执行新的成员写入；实际恢复必须经原脚本通道核对。不能承诺官方服务永远不要求本人登录或验证。

## 交接顺序

1. 普通程序暂停外部办理，保存故障与原日志，正常关闭浏览器和宿主。
2. 确认旧进程死亡、互斥已释放，短会话登记 cloud ticket 后退出。
3. 将一次性故障消息投递到管理员选定聊天；发送结果不明先查原回执，禁止重投。
4. Codex 限时诊断或核对原租约；ACK 只是结果请求。
5. 普通程序确认精确消息对应的会话已终结，重新只读核对官方名单并办理 finish。
6. 健康证据完整才恢复正常任务；结果不明保留原租约及执行权保护。泛化检查未恢复时按退避间隔只读复核，同一连续故障不再次唤醒模型。

## 配置

在本机 `.sites-runtime/agentless/config.json` 增加 `faultRescue`：`enabled`、`scope: "read_only_reconcile"`、管理员选定聊天的 `threadId`、`timeoutSeconds: 300`。可指定经过核对的本机 `cliPath`；否则只接受唯一的 Codex 桌面 CLI。通知方式是网页和 Codex 故障消息，不新增邮件或外部通知服务。

正常执行与网页三十分钟提醒不依赖模型；只有故障诊断可能消耗模型用量。Codex 应用、登录或工具服务不可用时保持故障记录，不能虚报“已恢复”。

有限恢复见 [V13-BOUNDED-RECOVERY.md](V13-BOUNDED-RECOVERY.md)。发布前全量回归、私有真实 D1、构建及本机无窗口只读核对的最终回执保存在版本发布报告；未经核对的人工操作不作为验收证据。回退步骤见本版回退文档。
